# P0 协议：证明"问题确实存在"

> 起因：导师质疑 **"没有实际证据表明问题确实存在"**。
> 本文档给一个**可执行、成本远低于主实验**的前置协议，用来回答这个质疑。
> 立场：**这个质疑是对的。你的实验计划从一个更靠后的位置开始了。**

---

## 0. 导师的质疑到底在问什么

"问题确实存在"可以有三层含义。**先分清是哪一层，否则你会答错题。**

| 层 | 质疑内容 | 需要的证据 | 最可能是？ |
|---|---|---|---|
| **A** | 「**模型自校正会失败**」这个现象没有数据 | 失败率 + 失败的可归因分解 | ★ **最可能** ★ |
| **B** | 「失败**可以被干预修复**」没有数据 | 干预的修复率 / oracle 上界 | 次可能 |
| **C** | 这个问题在你的任务域上**足够显著** | 发生率 + 置信区间 | 附带 |

**我的判断是 A（并连带 B）。** 理由在下一节。

## 1. 为什么这是一个真实缺口：看你的实验设计

你的 `paper-experiment-plan.md` 里有六个 RQ：

| RQ | 问的是 |
|---|---|
| RQ1 | 交互项的**符号**由什么决定 |
| RQ2 | "契合度"能否分解 |
| RQ3 | 是否存在协同→冲突的**相变** |
| RQ4 | 时点是否独立可操纵 |
| RQ5 | 同策略约束在 RL 下是否仍必要 |
| RQ6 | 能否打破顺序次优 |

**这六个全是"机制问题" —— 都在问"它怎么起作用"。**

**没有一个在问"不干预时，问题真的发生了吗"。**

### 这个缺口为什么致命

你的核心因变量是：

```
Δ²(d,k,τ) = [V(H_d,C_k) − V(H_d,C₀)] − [V(H₀,C_k) − V(H₀,C₀)]
```

**这是一个"差分的差分"。**

**它的前提是：四项各自都有非零效应。** 如果：

- `C₀`（无矫正）本身已经很好 → `V(H_d,C_k) − V(H_d,C₀) ≈ 0`
- `H₀`（基线 harness）本身已经够好 → `V(H_d,C₀) − V(H₀,C₀) ≈ 0`

**那么 Δ² 恒等于 0 —— 你的整个实验网格在测量一个不存在的东西。**

**更具体地说**：你的网格是 d∈{0..12} × C∈{C₀..C₃} × τ∈{τ₁,τ₂,τ₃}，**成本 $8k–25k**。

**而它成立的**唯一**前提是**：

> **在不加任何干预和矫正的基线（d=0, C₀）上，存在一个足够大的、由"harness 没能阻止、模型自己也没修好"造成的失败池。**

**这个池子有多大 —— 你没有测过，也没有任何文献在这个任务域上测过。**

**导师问的就是这个池子的水位。**

## 2. 核心区分：任务失败 ≠ 问题存在

**这是整个 P0 协议的关键。** 因为导师要的**不是"失败率"**。

**任务失败至少有三种，而只有第二种才是你的研究空间**：

| 类型 | 表现 | 干预有用吗 | 怎么识别 |
|---|---|---|---|
| **① 能力不足** | 模型**不知道**正确方向 | ❌ 没用（harness 不会让模型变聪明） | 轨迹里没有任何"正确方向的迹象" |
| **② 有能力未做** ★ | 模型**知道但没做**（或在错误方向上反复） | ✅ **这才是干预的空间** | 轨迹里出现正确方向的迹象，但没有被执行 |
| **③ 不可逆已发生** | 错误动作已经执行，收不回来 | ✅ 但需要的是**回滚**而非重试 | 有破坏性动作的轨迹 |

**所以"基线失败率 60%"这个数字，对你的研究几乎没有信息量。**

**你要的是**：

```
失败率 60%
  ├── 类型 ① 能力不足      ??%
  ├── 类型 ② 有能力未做     ??%   ← ★ 这个才是你的问题规模
  └── 类型 ③ 不可逆已发生   ??%   ← ★ 这个决定你需不需要回滚机制
```

**这三个问号，就是导师要的"证据"。**

（注意：这三个类型**正是你提的 A/B/C 分类** —— 见 `error-taxonomy.md`。）

## 3. P0 协议（可执行）

### 3.1 成本

| 项 | 估算 |
|---|---|
| 跑基线轨迹 | **100 条**（主域 60 + 复现域 40） |
| 每条约 10–25 步 | 约 2000 步 rollout |
| API 成本 | **远低于主实验**（无训练、无多臂） |
| 人工标注 | 100 条 × 5 分钟 ≈ **8 小时** |
| 总计 | **约 1 周**（含标注） |

**对比主实验的 $8k–25k 和 200–600 GPU 小时** —— **P0 是它的零头。**

### 3.2 步骤

```
步骤 1  跑基线
        H₀（最小 harness：只有循环 + 工具 + 日志）
        C₀（无任何矫正）
        在 100 道题上各跑 1 次
        ★ 必须记录完整轨迹（这正是你的会话日志要做的）

步骤 2  自动筛选失败轨迹
        用评测判分器分出失败集合 F（期望 40–70 条）

步骤 3  人工标注（★ 核心 ★）
        对每条失败轨迹，在"失败点"处判断：
          Q1: 轨迹里有没有出现"正确方向"的迹象？
              （比如：模型说出了正确的文件/函数，但改错了地方）
          Q2: 这个失败在发生时，是否已经产生了不可逆的动作？
          Q3: 如果人工在失败点插入**一个正确的下一步**，任务能完成吗？

步骤 4  统计
        报三个比率 + 95% CI（Wilson 区间）
```

### 3.3 三个标注问题各自的作用

| 问题 | 回答什么 | 对应类型 |
|---|---|---|
| **Q1** 有正确方向迹象吗 | **"有能力未做"的规模** | 类型 ② |
| **Q2** 有不可逆动作吗 | **"需回滚"的规模** | 类型 ③ |
| **Q3** oracle 插入能救回吗 | **干预的上界** | 见 §4 |

**Q1 和 Q2 是"问题存在性"，Q3 是"问题可解性"** —— **两个都要有，导师的质疑才被完整回应。**

### 3.4 输出格式（直接给导师看）

```
P0 结果（任务域：____，N=100，base model：____）

基线表现
  成功率        38.0%  95% CI [29.0, 47.8]
  平均步数      14.2（成功题 9.1 / 失败题 17.3）

失败分解（N=62）
  类型① 能力不足           26  (41.9%)  95% CI [30.3, 54.4]
  类型② 有能力未做         28  (45.2%)  95% CI [33.3, 57.6]   ← ★ 研究空间
  类型③ 不可逆已发生        8  (12.9%)  95% CI [6.7, 23.4]   ← ★ 需回滚
  （重叠：类型②③可同时出现，已单独计数）

oracle 上界（N=62）
  人工插入一个正确下一步后完成  31  (50.0%)  95% CI [37.9, 62.1]
  ★ 这就是"干预的理论天花板"

稳定性（每题重复 3 次的子集）
  失败类型的一致率          78%  κ = 0.66
```

**注意最后一行** —— **它回答的是"这个分类本身可靠吗"**（对齐你课程 M11 的 κ ≥ 0.6 判据）。

## 4. oracle 上界：比"失败率"强得多的一条证据

**Q3 的设计是这份协议里最重要的一环。**

```
对一条失败轨迹，人工在"失败点"插入**一个正确的下一步**
   ↓
让模型从这个新状态继续
   ↓
如果完成了 → ★ 说明这条轨迹的失败"可被一个动作修复" ★
```

**为什么它比"失败率"有用**：

| 证据 | 能说明什么 | 不能说明什么 |
|---|---|---|
| 失败率 62% | 有失败 | **失败是否可修** |
| 类型②占比 45% | 有"有能力未做"的迹象 | **迹象是否真的可转化为修复** |
| **oracle 上界 50%** | ★ **干预有一个 50% 的天花板** ★ | 自动诊断能不能达到它 |

**最后一行是关键**：**oracle 上界是"自动干预"的性能参照系**。

**你的主实验可以这样定位**：

> "oracle 干预能救回 50% 的失败；我们的自动干预达到了其中 X% ——
> **即我们实现了 oracle 上界的 X/Y 比例。**"

**这个说法比"我们的方法比基线高 5 个点"有力得多** —— 因为它**给增益定义了一个上限**。

**（这个"上界"的思路你应该眼熟 —— 就是 DARC 用"验证器支持的参考"做上界那一套。）**

## 5. go / no-go 判据

**P0 跑完，按这三个数决定主实验要不要做**：

| 情况 | 判据 | 结论 |
|---|---|---|
| **绿灯** | 类型②占比 **≥ 25%**，且 oracle 上界 **≥ 30%** | ✅ 主实验有对象，全力推进 |
| **黄灯** | 类型②占比 10–25% | ⚠️ 缩小范围（只做类型②的子集），并在论文里说明 |
| **红灯** | 类型②占比 **< 10%** | ❌ **主实验不应做** —— 见 §7 |

**为什么用 25% 这个门槛**：

```
如果类型②只占失败的 10%，而失败率是 60%
   ↓
问题规模 = 6% 的任务
   ↓
而你的干预还要在这个 6% 上有效果
   ↓
★ 需要的样本量会大到不现实 ★
```

**用 `n ≈ 4/Δ²` 反推**：如果你要在"6% 的子集"上证明 20 个点的提升，**需要约 1000 个该子集样本 = 16000 道题**。

**这就是"先测问题规模"的实际价值** —— **它决定你的实验在算术上是否可行。**

## 6. 怎么跟导师说

**不要说"我会补实验"。要说清你认识到了什么、以及它会改变什么。**

建议的结构（三句话）：

> **① 承认缺口的性质**（不是"我漏了一个实验"，而是"我的实验序列起点不对"）
>
> "您说得对。我的设计是从'干预和矫正怎么相互作用'开始的，
> 而它隐含了一个前提：**不干预时确实存在问题**。
> 这个前提我没有测过，网格里也没有一条臂在测它。"
>
> **② 给出可证伪的方案**
>
> "我准备加一个前置实验 P0：在纯基线上跑 100 条轨迹，
> 把失败分成'能力不足'和'有能力未做'两类，
> 再测一个人工干预的 oracle 上界。
> 三个数都是带 95% CI 的。"
>
> **③ 明确说出"什么结果会让我放弃"**
>
> "我的判据是：**如果'有能力未做'占失败的比例低于 10%，
> 说明这个问题在我的任务域上不成立 —— 那我就应该放弃这个方向**，
> 或者把结论改写成一个负面发现。"

**第 ③ 句是这段对话的重点。** 它展示的是**可证伪性** —— 而这正是导师在问的东西。

**导师质疑的不是"你做错了"，而是"你的研究有没有可能出错"。**
**你给出一个明确的失败条件，质疑就转化成了方法。**

## 7. 如果 P0 显示"问题不存在"

**这是必须提前想清楚的情况。** 三种可能的结果，三种处理：

| 结果 | 含义 | 怎么办 |
|---|---|---|
| **类型②占比很低** | 模型自我修正在这个域上**已经够好** | 这本身是**可发表的负面发现**（见下） |
| **oracle 上界很低** | 失败**不可修**（能力问题） | 转向"如何提升能力"，与 harness 无关 |
| **类型③占比很高** | 问题**主要是不可逆动作** | **转向"回滚机制"这个更窄的问题**（你的 C 类） |

**第一条不是失败，是发现。**

**在当前"人人都在加 harness"的语境下**：

> **「模型自我修正已经足够，harness 干预无增益」是一个反例价值很高的结论。**

**而且它对你自己更重要** —— 它**救你免于花 $8k–25k 去测量一个不存在的东西**。

**（这也正是 Hermes 那个"Nothing to save 是一等公民"的道理：
不为了显得有产出而制造产出。）**

## 8. 与主实验计划的关系

**P0 不是推翻你的计划，是给它补一个地基。**

```
P0（新增，前置，约 1 周）
  ├─ 证明问题存在（类型②的规模）
  ├─ 给出干预的上界（oracle）
  └─ 校准失败分类器的可靠度（κ）
        │
        ▼
E1–E8（你现有的网格，$8k–25k）
  └─ 全部照旧，但多了一个"问题规模"的锚点
```

**而且 P0 会改进主实验的设计**：

| P0 的发现 | 对主实验的改进 |
|---|---|
| 类型②集中在某几类任务 | **收窄任务域**（提高问题密度，降低所需样本量） |
| oracle 上界是 50% | **给 Δ² 一个解释尺度**（"我们达到了上界的 X%"） |
| 类型③占比不低 | **必须加一个"回滚"臂**（你现在的网格里没有） |
| 失败分类的 κ = 0.66 | **可以放心用自动分类器**；κ 低就必须人工 |

**最后一行值得展开**：**如果分类器不可靠，那"只启用对应类别的恢复策略"（τ₃ 的设计）就建立在流沙上。**

**P0 顺便把这个风险也测了。**
