# 研究方案：失败的可恢复性边界（Recovery Boundary）

> 决策记录：**主选题 A**（错误类型 × 干预方式的匹配矩阵）+ **环境 A**（自搭环境 + benchmark 子集）
> 实验路线：**路线 A（全推理期，不训练）** + **本地 7B–14B** + **2×4090**

---

## 1. 研究问题与假设

### 1.1 主问题

> **在 LLM agent 任务中，不同类型的失败，分别需要什么类型的干预？
> 是否存在"干预无效"的失败类别？**

### 1.2 三个假设

| # | 假设 | 如果成立 |
|---|---|---|
| **H1** | 失败**不是同质的** —— "有能力未做" 占显著比例（>15%） | 干预有空间 |
| **H2** | **类型 × 干预 存在交互** —— 不同失败需要不同干预 | ★ 核心贡献 ★ |
| **H3** | **不可逆性取决于 harness 能力**，而非任务本身 | 反驳"不可逆是任务的客观属性" |

**H3 是本文最有价值的原创主张**，见第 3 节。

---

## 2. ★ 三类失败的可操作定义（本方案的核心）★

**这是全案的成败关键** —— 因为"能力不足"和"有能力未做"的区分**必须靠证据，不能靠人肉感觉**。

### 2.1 类型① · 能力不足（Capacity Gap）

**操作定义**：

```
条件 A：pass@n 仍失败（n ≥ 8，temperature 0.8）
条件 B：给"步骤级提示"（不含答案）后，成功率无显著上升
   ↓
判定为「能力不足」
```

**含义**：**怎么试都不行** → 干预大概率无效。

### 2.2 类型② · 有能力未做（Capability–Execution Gap）★ 核心类别 ★

**操作定义**：

```
条件 A：pass@n 成功（n ≥ 8），但 pass@1 失败
条件 B：给"步骤级提示"后成功率显著上升（> 2× pass@1）
   ↓
判定为「有能力未做」
```

**含义**：**模型有能力，但首次没执行出来** → ★ **这才是干预的空间** ★

**诊断量的计算**：

```
Δ_capability = pass@n − pass@1
```

**这个差值就是"能力上界与表现下界的距离"** —— 距离越大，干预空间越大。

**⚠️ 关键区分**：**"多试几次成功" ≠ "干预成功"**

- **pass@n 是诊断工具**（衡量能力上界）
- **干预实验必须在等采样预算下比较**（见第 6 节）

**否则你只是把"重采样"包装成了"干预"** —— 这正是 R06 批评前人的地方。

### 2.3 类型③ · 不可逆污染（Irreversible Contamination）

**操作定义**：

```
条件 A：环境状态偏离目标状态（文件 / 数据 / 会话）
条件 B：在当前 harness 能力下，不存在 oracle 动作序列能恢复
   ↓
判定为「不可逆污染」
```

**关键**：**条件 B 里的"在当前 harness 能力下"是刻意加的** —— 它引出 H3。

---

## 3. ★ 原创主张 H3：不可逆性是 harness 的属性，不是任务的属性 ★

**这是本文区别于所有已有工作的论点。**

**论证**：

```
同样是"删错文件"这个动作：
   ├── 在无快照的 harness 里 → 不可逆
   └── 在有快照/回滚的 harness 里 → 可逆
         ↓
★ 所以「不可逆」不是任务的内在属性，
   而是「任务 × harness 能力」的联合属性 ★
```

**为什么这个主张有价值**：

| 已有工作的隐含假设 | 本文的主张 |
|---|---|
| "有些失败是没法恢复的"（把不可逆当作任务属性） | **"不可逆"取决于 harness 提供了什么** |
| → 结论是"没办法" | → **结论是"harness 可以把不可逆变成可逆"** |

**这是"harness 干预"的合法性来源** —— 而且**它可测**（见第 4 节的 H 轴）。

---

## 4. 因子设计（三轴）

```
因子 A  T 失败类型   {T₁ 能力不足, T₂ 有能力未做, T₃ 不可逆污染}    ← 分层变量（非随机）
因子 B  S 干预方式   {S₀ 无, S₁ 原地重写, S₂ 换策略, S₃ 结构化反思, S₄ 外部验证}
因子 C  H harness 能力 {H₀ 无快照, H₁ 有快照回溯}                   ← ★ 原创轴 ★
```

**主指标**：

```
R[T][S] = P(恢复 | 失败类型 T, 干预方式 S)
   ↓
★ 一张 3×5 的恢复率矩阵（含 H 轴则 ×2）★
```

**核心结论形态**：

```
              S₀   S₁   S₂   S₃   S₄
T₁ 能力不足   低   低   低   低   低
T₂ 有能力未做 低   低   ★高★ ?   高
T₃ 不可逆污染 低   低   低   低   ★仅 H₁ 下高★
                    ↑                ↑
              ★ 这两个格子就是论文 ★
```

**★ 矩阵的形状本身就是要发表的发现 ★** —— 而不是"我的方法赢了"。

## 5. 环境设计（自搭 + benchmark 子集）

### 5.1 双轨环境

| 轨 | 用途 | 内容 |
|---|---|---|
| **自搭环境** | ★ **可控地制造三类失败** ★ | 自家 harness + 设计过的任务（能精确控制失败类型） |
| **标准子集** | **外部效度** | BFCL / ToolBench / AgentBoard 的一个子集 |

**自搭环境的任务设计原则**：

| 目标类型 | 任务怎么设计 |
|---|---|
| T₁ 能力不足 | 需要超出模型能力的推理（如多约束规划） |
| **T₂ 有能力未做** | ★ **简单但易错**：信息在上下文里，模型容易忽略 ★ |
| T₃ 不可逆污染 | 包含破坏性操作（删除 / 覆盖），且在 H₀ 下无快照 |

### 5.2 ⚠️ 第一个必须先验证的事：成功率区间

```
7B 在候选环境上的成功率必须落在 30%–70%
   ├── 太低（<20%）→ 失败全是"能力不足"，无分类意义
   └── 太高（>80%）→ 没有失败可分析
```

**做法**：**每个候选环境先跑 50 题**，看落在哪个区间。

**这一步在正式实验前完成**（半天）。

## 6. ★ 方法论底线：等算力对照 ★

**这是 R06 的批评标准，必须沿用。**

**R06 的原文做法**：

> 多智能体辩论 vs self-consistency，在**相同推理预算**下比较：**83.0 vs 88.2**

**如果你的干预只是"多给几次机会"，那它不是干预，是重采样。**

**具体规则**：

| 规则 | 说明 |
|---|---|
| **1. 总 token 预算相等** | 干预组与对照组的生成 token 总量匹配 |
| **2. 总步数预算相等** | 避免"干预 = 更多步" |
| **3. 对照组用 self-consistency** | ★ **不用 greedy pass@1** ★ —— greedy 是弱对照 |
| **4. 报告 Δ_capability** | 让读者看到干预离"能力上界"还有多远 |

**第 3 条尤其重要** —— 很多论文的"提升"来自和 greedy 比，**那是虚的**。

## 7. 指标与样本量

### 7.1 主指标

```
R[T][S]        恢复率
Δ_capability   pass@n − pass@1（能力上界与表现下界的距离）
CE            干预效率 = (R − R_S0) / token 增量
```

### 7.2 样本量

**按 `n ≈ 4/Δ²`**（检测两点比例差）：

| 检测的差异 | 每格需要 | 格子数 | 总 trial | 本地耗时 |
|---|---|---|---|---|
| 15 个点 | ~180 | 3×5=15 | 2700 | 几小时 |
| **10 个点** | **~400** | **3×5=15** | **6000** | **< 1 天** |
| 5 个点 | ~1600 | 15 | 24000 | 1–2 天 |

**推荐起点**：**每格 400 条，共 6000 trial** —— 本地 7B 推理**一天内可完成**。

**置信区间**：每个格用 **Wilson interval**（小样本比例的标准做法），**不用正态近似**。

### 7.3 统计检验

- **主检验**：类型 × 干预的**交互效应**（logistic 回归 + 交互项，或双因素方差分析）
- **多重比较**：15 个格子 → **Benjamini-Hochberg 校正**
- **预注册**：**在做实验前把假设和判据写死**（防"看数据找结论"）

## 9. ★ 预案：如果矩阵的形状不是你想的那样 ★

**这是"可失败选题"的关键 —— 三个方向都能写。**

| 结果 | 论文的主张 | 价值 |
|---|---|---|
| **所有格子恢复率高** | "agent 失败基本可恢复" → **反驳 R06 在 agent 场景的推广** | ✅ 有价值（挑战经典结论） |
| **所有格子恢复率低** | "干预无效，能力是瓶颈" → **支持 R06** | ✅ 有价值（加固经典结论） |
| **存在显著交互** | ★ **"类型匹配才是关键"** ★ | ✅ **最强结果** |
| **H₁ 显著高于 H₀** | "不可逆性可被 harness 消除" | ✅ 独立贡献 |

**没有一种结果是"白做"** —— 这是这个选题设计的核心。

**唯一会白做的情况**：**标注不可靠**（三类分不开）。
→ 所以**第 2 节的判据必须先用 50 条轨迹试标，算标注一致性（Krippendorff's α ≥ 0.7）**。
