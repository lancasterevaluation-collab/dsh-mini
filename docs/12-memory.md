## L0 要解决的问题

第 11 步结束时，harness 能跑任务了。但它**每次都是从零开始**。三个具体现象：

**现象 1：同样的纠正要说第二遍。**
用户在任务 1 里说"这个项目用 pnpm"，任务 2 里模型又 `npm install` 了一次。

**现象 2：跑得糟，但模型不知道。**
任务 1 里同一个工具连续失败 3 次、重试了 4 次、步数烧掉 7/8。这些事实**全都在日志里** —— 但模型看不到，因为日志里没有"你已经重试 4 次了"这句话。下一次它还会用同样的方式失败。

**现象 3：想记住，但记不住多久。**
最直觉的做法是 `agent.remember(text)`。然后它越记越多，直到某天上下文预算被记忆吃满 —— 而那一天之前没有任何警告。

这一步解决前两个。第三个的答案不是"记得更多"，而是"**明确地记不下**"。

## L1 设计与原理

### 1.1 容量是硬上限：写满即拒绝，而不是淘汰最旧

```ts
memory.add(draft)   // 满了 → 抛 MemoryFullError，异常里带着合并建议
memory.merge(ids)   // 合并 k 条为 1 条 —— 唯一能腾出空间的方式
```

**为什么不用 LRU/FIFO 淘汰？** 因为记忆不是缓存。

淘汰最旧在缓存里是对的（最近没用的就是没用的），在记忆里是错的：**最旧的那条可能正是"用户从一开始就强调的约束"**。
而合并把它保住 —— 两条关于同一件事的记忆合成一条更准的，信息不丢、条目变少。

代价是"谁来合并"变成了必须回答的问题。我们把它交给模型：只有它知道两条记忆说的是不是同一件事。**门控（第 16 步）负责不让合并变成"删掉不同意的"**。

### 1.2 异常要携带可执行的下一步

```ts
export class MemoryFullError extends Error {
  readonly suggestions: readonly string[]   // 建议合并哪几条
  readonly limit: number
}
```

报错信息是：

```
记忆库已满（3 条）。请先用 merge(ids, text) 合并以下条目之一：mem-1 / mem-3
```

**为什么异常里要塞建议？** 因为调用方（模型）需要的是"接下来该做什么"，不是"你失败了"。
一个只说"满了"的异常会让模型反复重试同一个动作 —— 这正是第 15 步诊断里 `feedback-resistance` 那一类的成因。

建议怎么算？同 scope + 词重叠度最高的两对。极简但有效：不引入分词依赖，而"pnpm"和"workspace 配置"这样的词重叠足以把同话题的排到前面。

### 1.3 每条记忆必须有 source

```ts
readonly source: MemorySource   // { sessionId, seq }
```

因为它决定了记忆库是"可审计的知识"还是"不可查证的传言集散地"。
第 14 步的"派生结论而非存原文"建立在这条之上：任何结论都能回到原始事件。

### 1.4 Nudge：提醒必须走任务的入口，不能插进会话中间

三个真实场景：

| 观察到 | 提醒 |
|---|---|
| 同一次任务重试 ≥2 次 | 这次先核对参数与环境，不要用同样的方式反复重试 |
| 同一个工具连续失败 ≥2 次 | 方法不对而不是运气不好，先读清楚再调用 |
| 步数用掉 ≥80% 或触顶 | 优先做最关键的几步，尽早给结论 |
| 守卫拦下 ≥2 次 | 确认操作在工作目录内、且没有重复调用 |

**关键设计：提醒不 append 进会话，而是在下一次任务开始之前拼进任务文本。**

为什么？因为会话是 **append-only 的事实记录**。往里塞一句"系统觉得你该少试几次"，会让"模型看到的历史"里混进**不是模型产生、也不是用户说的**内容，而第 7 步的核心不变量是"模型看到的都能从日志重建"。

走任务入口则留下两条可查证据：`agent/task-ready` 事件的改写、以及日志里那条真实的 `user/message`。

拼装时放在**前面**是刻意的：模型对开头的约束最敏感，把提醒塞在长任务描述后面等于没说。

```ts
static compose(task: string, nudges: readonly string[]): string {
  return ['【系统提醒】', ...nudges.map((line) => `- ${line}`), '', '【任务】', task].join('\n')
}
```

### 1.5 规则可插拔，且不重复堆积

"什么算跑得糟"是部署决定（教学看重试次数，生产可能看 token 花费），所以规则是对象、可按 profile 装载。

另外 `observe()` 里有一条去重：同一条规则已经待注入时不再追加。否则第二次观察会让提醒翻倍，第三条任务上带着四句一样的话 —— 那是噪声，不是提醒。

## L2 决策表

| # | 决策 | 我们的选择 | 替代方案 | 代价落在谁身上 |
|---|---|---|---|---|
| 1 | 满了怎么办 | 拒绝 + 给合并建议 | 淘汰最旧 / 无限增长 | **模型**：它必须真的去合并，多一次工具调用 |
| 2 | 合并粒度 | 显式 `merge(ids, text)` | 自动按相似度合并 | **库的实现者**：自动合并会误合（把"用 pnpm"和"用 npm"合成一条） |
| 3 | 置信度来源 | 观测次数（`1 - 1/(n+1)`） | 模型自报把握 | **模型**：它不能一次就把自己的一句话变成高置信结论 |
| 4 | 记忆作用域 | `global` / `project` 两档 | 按会话 / 按用户+项目+时间多维 | **使用者**：两档覆盖 90% 场景，多了要维护策略 |
| 5 | 提醒的通道 | 任务文本前缀 | append 一条 system 消息 | **日志的完整性**：前者可重建，后者不行 |
| 6 | 提醒去重 | 同规则只留一条 | 每次都追加 | **排查者**：看不到"提醒了几次"，但换来输出可读 |
| 7 | 提醒是否自动注入 | 是（`inject: true` 可关） | 只记录不注入 | **模型**：它会在每轮开头多读几行 |

## L3 实现与验证

### 3.1 文件清单

| 文件 | 职责 | 关键点 |

### 3.2 三条接线（都在 `plugins/evolution.ts`）

```ts
ctx.on('session/event', (payload, next) => {
  // 索引历史 + 观察用户信号
  return next()          // ★ 忘了这行，后面的监听器全部静默失效
})

ctx.on('agent/turn-end', (payload, next) => {
  nudge.observe(view)    // 判定"这次跑得糟吗"
  curator.review()       // 顺便打扫技能（幂等）
  return next()
})

ctx.on('agent/task-ready', async (payload, next) => {
  const downstream = await next()      // 先让下游处理，再在它的结果上包装
  const base = typeof downstream === 'string' ? downstream : payload.task
  return [...blocks, '【任务】', base].join('\n')
})
```

第三段的顺序值得注意：**先 `await next()` 再包装**。这样多个插件可以串联改写任务，而不是互相覆盖（谁先返回谁赢）。

### 3.4 验收判据

| 判据 | 怎么验 | 期望 |
|---|---|---|
| 写满即拒绝 | 容量 3 时写第 4 条 | 抛 `MemoryFullError`，异常里带建议 |
| 合并腾空间 | `merge([a,b], text)` | 条数减 1，`mergedFrom` 记录来源数 |
| 不淘汰最旧 | 写满后检查第一条还在 | 用 `list()` 断言早期条目仍在 |
| 提醒判定 | 构造"重试 3 次 + 工具失败 3 次 + 守卫 2 次"的视图 | 命中 3 条规则 |
| 不重复堆积 | 同一视图 `observe()` 两次 | 第二次新增 0 条 |
| 干净 turn 不提醒 | 正常视图 | 命中 0 条 |
| 注入可查 | 集成演示的第 2 次任务 | 提醒出现在 `user/message` 里 |

## L4 仍未解决

| 缺陷 | 后果 | 修法 | 当初为什么这么选 |
|---|---|---|---|
| **合并建议靠词重叠** | 中文近义（"简短" vs "简洁"）不会被认为是同一话题 | 引入字符 n-gram 或小词典归一 | 零依赖下分词成本高；建议只是"排序提示"，错了也不致命 |
| **记忆不会自动失效** | 用户改主意后旧记忆仍在（"用 pnpm" 永远不会过期） | 加 `expiresAt` 或"被否定"事件 | 过期策略需要用户输入；先做显式 `remove()` |
| **提醒可能造成噪声** | 每个任务开头都带四句话，模型可能开始忽略它们 | 加"提醒生效验证"：下一次命中同一规则则提升强度 | 验证需要对照组，属于课程外 |
| **nudge 只在 turn 边界产生** | 一次 turn 内部的自我修正机会完全没有（比如第 3 步就发现走偏了） | 在 `step/end` 上也挂规则 | 每步提醒会让日志爆炸，先做粗粒度 |
| **记忆与技能没有交叉引用** | 一条记忆无法指向"该用哪个技能" | 在 `MemoryEntry` 里加 `skill?: string` | 第 13 步的库还没有，先不耦合 |
