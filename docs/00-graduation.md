# 能力矩阵与毕业标准

> 本文回答一个问题：**学完这门课，我到底能做到什么？怎么证明我做到了？**
>
> 结论前置：**核心运行时 100% 可达；DSH 的外围能力（Web/桌面/协议/系统级）不在本课范围内，但有明确的补齐路径。**

---

## 0. 先把「完全独立做出 DSH」拆开

DSH 的真实体量：**307 个包 / 1932 个 src 文件 / 347 篇文档**。

| 部分 | 体量 | 本课程 | 说明 |
|---|---|---|---|
| **框架本体** `vendor/cordis/` | 9 文件 | ✅ **100% 覆盖** | 整个体系的地基 |
| **核心能力** `packages/core/` | 45 文件 | ✅ **约 70% 覆盖** | agent / loop / session / tools / prompt / scope |
| **LLM 接入** `packages/llm/` | ~30 文件 | ✅ 约 40% | 单 provider + 重试；不做多路由 |
| **可靠性与安全** `guard/` `interaction/` `sandbox/` | ~25 文件 | 🔶 约 50% | 做策略与守卫；不做 OS 级沙箱 |
| **持久化** `session/` `storage/` `session-query/` | ~35 文件 | 🔶 约 40% | 做 append-only + FTS；不做格式版本迁移链 |
| **组合与启动** `bundle/` `boot/` | ~30 文件 | ✅ 约 60% | 做装载与层叠；不做 pnpm 解析、schema 生成 |
| **外围能力** web/mcp/lsp/terminal/browser/computer | ~150 文件 | ❌ 不做 | 是"在框架上新增能力"，会了框架就能自己加 |
| **多端** client/host/api/typert/sdk/acp/python | ~700 文件 | ❌ 不做 | 需要另外学 Web、Electron、RPC |
| **工程设施** CI、快照测试、i18n、覆盖率门 | ~300 文件 | ❌ 不做 | 属于工程实践，非架构 |

**结论**：本课程结束时，你会拥有的是 ——

> **DSH 的完整架构骨架 + 一条能跑通任务的纵切面。**
> 你能读懂并改动能读懂的一切；能独立新增任何"能力型"插件；不能独立做出 Web/桌面/跨语言协议这三块（那是另一门课）。

这句话我会在第 16 步结束时再确认一遍，不会中途改口。

## 1. 五级能力定义

学习目标不能只写"掌握"，必须分级，否则无法自检。

| 级别 | 名字 | 判定标准 | 怎么验证 |
|---|---|---|---|
| **L1** | 读懂 | 能用自己的话解释这段代码**为什么**这么写 | 合上文档，口述 3 分钟 |
| **L2** | 改动 | 能按需求改一处，且知道会牵连什么 | 改完能通过已有的验收判据 |
| **L3** | 重建 | **关掉文档**，从零写出这个部件 | 写完能通过全部演示 |
| **L4** | 设计 | 能为一个新需求选择扩展点并设计接口 | 说出「挂在哪、为什么、代价是什么」 |
| **L5** | 评审 | 能判断别人的设计对不对 | 给一份陌生代码，指出分层/边界问题 |

**L3 是分水岭。** 能读懂（L1）不等于能写（L3）—— 大部分"学完还是不会做"都卡在这里，因为读的时候大脑在偷懒（"哦，有道理"），写的时候才发现每个细节都没想过。

**本课程的设计目标：每个核心部件都让你达到 L3。**

## 3. 毕业标准（五项可验证检验）

**全部通过才算学完。每一项都能自己判定，不需要别人打分。**

### 检验 1 · 从零重建（最重要）

```
条件：一个空目录，4 小时，允许查 glossary.md，**不允许看任何已有代码**
产出：一个能跑通「读取文件 → 回答」的 mini harness
```

必须包含：模型层、工具注册表、ctx 容器、会话日志、agent 循环。

**这是唯一能证明 L3 的检验。** 如果重写时卡在"那个字段叫什么来着"，说明还是 L1。

### 检验 2 · 架构评审

```
条件：给你一份陌生的 agent 代码（比如你自己第 3 步之前的版本）
产出：指出它的分层问题，并说明应该怎么改
```

参考答法：「`kernel/llm.ts` 里 import 了 `framework/context.ts`，依赖方向反了 —— kernel 是纯能力层，不该认识框架。」

### 检验 3 · 新增扩展点

```
条件：不查教程，给 lab 加一个课程里没出现过的新能力
建议题目（任选其一）：
  a. token 预算控制：累计消耗超过阈值就停止本 turn
  b. 文件监听：工作目录变化时注入一条系统消息
  c. 工具结果缓存：相同参数的调用直接复用上次结果
产出：实现 + 说明「挂在哪、为什么、代价是什么」
```

这一项检验的是 **L4**：你能否在一个没见过的需求上选对扩展点。

### 检验 4 · DSH 源码导航

```
条件：给一个需求描述，不给文件路径
题目示例：
  a. "DSH 里模型请求失败重试的策略定义在哪？默认重试哪些错误码？"
  b. "DSH 怎么保证工具调用前必须过审批？"
  c. "DSH 的会话日志为什么能支持从任意历史点 fork？"
产出：15 分钟内给出文件路径 + 关键设计说明
```

工具是允许的：`rg`、`--dump-config`、已有的映射表。

### 检验 5 · 故障诊断

```
条件：一个行为异常的 harness（比如"重试没生效"）
产出：在不读全部代码的前提下定位原因
```

这一项检验的是**你脑子里有没有一张完整的机制地图** —— 知道"重试没生效"应该去查①插件是否装载、②事件是否分发、③监听器是否短路错了、④错误分类是否匹配。

## 4. 每阶段的挑战题（不给答案）

**这些题目故意不提供答案** —— 因为提供答案会毁掉它们的全部价值。

### Phase 0 挑战
1. 给 `MockProvider` 加一个"流式"模式：把完整回复拆成多个分片依次返回。然后让 `agent` 也支持它。
2. 给 `ToolRegistry` 加一个"单次调用超时"包装，超时返回失败结果而非抛异常。
3. 不查文档，写出 `toWireMessages` 存在的**三个**理由。

### Phase 1 挑战
1. **关掉文档**，从零重写 `context.ts`，要求装载失败时回滚干净。
2. 加一个能力：profile 里写了未知字段要在装载时报错，并指出是哪个文件的哪一行。
3. 设计：同一个 harness 进程里，跑一个"只读审查 agent"和一个"可写实现 agent"，两者工具集不同但共享同一个 `llm` 和 `session`。画出服务归属。

### Phase 2 挑战
1. **关掉文档**，从零写出 agent 循环，要求三种结束路径都正确（模型说完 / 步数超限 / 被取消）。
2. 加一个"token 预算"插件：累计超过阈值就停止本 turn 并返回提示。
3. 加一个"写文件前必须先读过"的守卫（模仿 DSH 的 read-before-edit 检查）。

### Phase 3 挑战
1. 设计一个新的学习信号：从失败轨迹里提取"要避免的模式"，并说明它与 Hermes 技能库的关系。
2. 让第 15 步的诊断器输出能被人工验证：构造 60 条人工标注，算出 κ 并判断是否达标。
3. 设计一个门控规则，能拒绝"连续 5 次小改动累积导致退化"的情况（这是 DSH 课程 M12 里提到的真实故障）。

## 5. 从 lab 到真实 DSH 的迁移路径

学完 16 步后，按这个顺序进入 DSH 源码：

| 序 | 做什么 | 用我们的什么 | 预期耗时 |
|---|---|---|---|
| 1 | 读 `vendor/cordis/src/` 全部 9 个文件 | 对照 `framework/context.ts` + `events.ts` | 2 小时 |
| 2 | 读 `packages/core/agent-loop/` 全部 8 个文件 | 对照 `plugins/agent-loop.ts` | 3 小时 |
| 3 | 读 `packages/core/session/` | 对照 `plugins/session.ts` | 3 小时 |
| 4 | 跑 `dsh --profile web --dump-config`，对照 `bundles/*.json` | 第 6 步的装载器 | 1 小时 |
| 5 | 按 `reference/dsh-file-map.md` 逐包读 | 映射表会告诉你"这个包对应我们的哪个文件" | 按需 |
| 6 | 给 DSH 写一个自己的插件（profile + patch） | 第 3、6 步 | 半天 |

**第 1、2 步是关键**：读完之后你会发现，那 1932 个文件里**没有新机制**，只有同一个框架上的不同能力。

## 6. 本课程不覆盖的部分与补齐路径

诚实清单：

| 不覆盖 | 为什么 | 怎么补 |
|---|---|---|
| **Web GUI**（59 个 client 包） | 需要 React / 前端工程 | 那是独立一份技能，与本课程正交 |
| **Electron 桌面端** | 需要 Electron 知识 | 同上 |
| **跨语言 SDK / RPC**（typert/api/python） | 需要协议设计与代码生成 | 学完本课程后读 `docs/graph-atlas.md` |
| **OS 级沙箱**（bwrap/Landlock/Seatbelt） | 需要系统编程 | 我们只做策略层；内核能力另学 |
| **LSP / PTY 终端 / 浏览器自动化** | 属于"能力插件"，不属于架构 | 会了框架后按 `packages/README.md` 逐个看 |
| **CI 门禁 / 快照测试体系** | 工程实践 | 读 `docs/testing.md` |
| **会话格式版本迁移链** | 复杂的向后兼容工程 | 读 `docs/session-format-status.md` |

**注意最后一列的形态**：除了前三项，其余都可以**用本课程的框架知识 + 读对应文档**自行补齐。这正是"会了框架，外围都是插件"的具体含义。

## 7. 怎么用这份文档

| 时机 | 做什么 |
|---|---|
| **每步学完** | 对照第 2 节的矩阵，确认自己至少到 L1；能到 L3 就别停在 L1 |
| **每阶段学完** | 做第 4 节的挑战题，**卡住了说明该阶段没学透，回去补** |
| **全部学完** | 做第 3 节的五项毕业检验 |
| **卡住时** | 回来看第 0 节，确认自己卡在"真问题"还是"量级问题" |

**最重要的一条**：

> **不要用"读完了"欺骗自己"学会了"。**
> L1 是读出来的，L3 是写出来的。矩阵里凡是标 L3 的，都必须**关掉文档重写一遍**才算达成。
