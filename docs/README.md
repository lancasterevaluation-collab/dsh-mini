## 文档写作纪律

### 每篇课程文档的固定结构（16 节）

**这是"学完能独立做"标准下的新模板**，以 `01-llm.md` 为标杆。

| # | 节 | 内容 | 为什么必须有 |
|---|---|---|---|
| 1 | **元信息** | 文件名 / 行数 / DSH 对应 / 目标级别 / 预计阅读与动手时间 | 让读者知道投入 |
| 2 | **本篇新词** | 本篇首次出现的术语 + 一句话 + "为什么必须懂" | 消灭"查词税" |
| 3 | **第 0 节 · 成品预览** | 你要做出什么、运行起来什么样、在课程中的位置 | 先看地图再走路 |
| 4 | **第 0.5 节 · 系统视角** ★ | 上下游关系、**连锁影响分析**（改错这里会波及哪几步） | **整体性系统思维** |
| 5 | **L0 要解决的问题** | 上一步留下的具体缺陷，带现象和报错原文 | 缺陷驱动，不喊口号 |
| 6 | **L1 设计与原理** | 为什么这么设计；关键概念；原型对比 | 理解而非记忆 |
| 7 | **L2 决策表** | 决策 × 选择 × 替代方案 × 代价落在谁身上 | 训练设计判断力 |
| 8 | **L3 实现（逐行讲解）** | **完整代码 + 逐行/逐块解释** | 核心增量：每个变量每行代码都讲 |
| 9 | **L4 运行与验证** | 运行命令、输出逐条解读、验收判据表 | 可自检 |
| 10 | **L5 语法速查** | 本篇出现的全部 TS 语法 + 易踩的坑 | 零基础必需 |
| 11 | **L6 关文档重写判据** | 必须能写出哪些部分、卡住时问自己什么、分级判定 | **L3 的唯一证明** |
| 12 | **L7 挑战题** | 不给答案的设计题 | 训练 L4 |
| 13 | **L8 自检清单** | 理解层 / 实现层 / 语法层 / 工程层逐条打勾 | 自我评估 |
| 14 | **L9 仍未解决** | 分两类：后续会解决的 + **当前实现的真实缺陷** | 诚实；DSH 每包都有此章 |
| 15 | **L10 提问训练** ★ | 五种提问模板 + 本篇引出的好问题 + **问题升级练习** | **教你怎么提问** |
| 16 | **L11 系统影响回溯** ★ | 读完全篇后重看第 0.5 节：哪些判断被推翻了 | 闭环检验 |

### 三条贯穿全文的机制（★ 机制）

| 机制 | 形式 | 训练什么 |
|---|---|---|
| **「停下来想一想」** | 散布在各节末尾的提问块，**不给答案** | 主动加工，而非被动接收 |
| **「先问再答」** | 在给出我们的设计选择**之前**，先问"你会怎么选？" | 设计判断力 |
| **「问题升级」** | 把模糊问题改写成精确问题的练习 | **提出好问题的能力** |

### 三条铁律

| 铁律 | 说明 |
|---|---|
| **逐行讲解** | 代码必须与真实文件一字不差，然后逐行/逐块解释"做什么 + 为什么 + 不这样会怎样" |
| **缺陷要坦白** | L9 必须列出当前实现的真实缺陷（不是"后面会做"，而是"这里现在就是不够好"） |
| **术语三层兜底** | 新词栏 + 正文首现解释 + `glossary.md` 兜底，缺一层即不合格 |

### 为什么要有「系统视角」和「提问训练」

这两节针对的是两类失败模式：

| 失败模式 | 症状 | 对应机制 |
|---|---|---|
| **碎片化** | 每一步都懂了，但说不出"它们在系统里怎么咬合" | 第 0.5 节 + L11 |
| **不会提问** | 遇到看不懂的地方，只能说"这里不懂"，问不出精确问题 | L10 + 问题升级练习 |

**"能提出精确的问题"是独立研究者最重要的能力之一** —— 它决定了你能否自己找到答案，而不是等人喂。
