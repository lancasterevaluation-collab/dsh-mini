## 第 1 节 · 一句话说清这篇论文

> **即使给模型「接近完美的外部反馈」，它仍然改不对自己的答案 —— 作者把这种现象命名为 FEEDBACK FRICTION（反馈摩擦）。**
>
> **而且他们证明了：主要障碍不是「反馈质量差」，而是「模型抗拒采纳反馈」。**

**关键词**：`near-ideal feedback`（接近理想的反馈）、`plateau below ceiling`（停在天花板之下）、`Feedback Resistance`（反馈抵抗）。

## 第 3 节 · 问题：什么叫"反馈摩擦"

### 3.1 "摩擦"这个比喻在说什么

**物理里的摩擦**：你推一个箱子，给它足够大的力，按牛顿力学它就该动 —— **但摩擦把一部分力吃掉了**。

**论文里的类比**：

```
你给模型正确的反馈（= 推力）
按道理它应该改对（= 箱子应该动）
   ↓
★ 但它没有完全改对 —— 一部分"改正的动力"被消耗掉了 ★
   ↓
这个被消耗掉的部分，就叫「反馈摩擦」
```

**为什么这个命名重要**：它**把问题从"反馈不够好"转成了"反馈没有被采纳"** —— 这是一个完全不同的诊断。

### 3.2 两种可能的解释，以及论文的选择

| 解释 | 预测 | 如果是它，该怎么解决 |
|---|---|---|
| **① 反馈质量不够** | 反馈越好 → 改善越大 | 生成更好的反馈（更强的反馈模型、更详细的分析） |
| **② 模型抗拒反馈** | 反馈已经很好 → 改善仍然有限 | ★ 反馈这条路走不通，要换机制 ★ |

**论文用实验排除了①** —— 这就是它最有价值的地方。

**怎么排除的**：

```
设计三级反馈 F₁ < F₂ < F₃
   ↓
F₃ 是「强模型反思反馈」，包含最终答案 + 完整解法（在可得时）
   ↓
如果①成立：F₃ 应该接近天花板
★ 实测：F₃ 确实提升很大（AIME +26.7%），但仍然停在远低于天花板处 ★
   ↓
★ 所以瓶颈不在反馈质量 ★
```

## 第 4 节 · 方法：受控迭代框架

### 4.1 框架图（❓ 我按描述重绘，非原文 Figure 2）

```
┌─────────────────────────────────────────────────────────────────────┐
│  一个问题 q                                                          │
└─────────────────────────────────────────────────────────────────────┘
                              │
                              ▼
                 ┌────────────────────────┐
                 │  ① 求解模型（solver）   │
                 │     给出初始答案 a₀     │
                 └────────────────────────┘
                              │
                    ┌─────────┴─────────┐
                    ▼                   ▼
              ┌──────────┐        ┌──────────────┐
              │  正确 ✓  │        │   错误 ✗     │
              └──────────┘        └──────────────┘
                    │                   │
              ★ 保留，不再迭代 ★         ▼
                    │       ┌──────────────────────────────┐
                    │       │  ② 反馈生成器                  │
                    │       │  ★ 能访问「近乎完整的标准答案」★ │
                    │       │     生成针对性反馈 f           │
                    │       └──────────────────────────────┘
                    │                   │
                    │                   ▼
                    │       ┌──────────────────────────────┐
                    │       │  ③ 求解模型带着反馈重试         │
                    │       │     a₁ = solver(q, a₀, f)     │
                    │       └──────────────────────────────┘
                    │                   │
                    └──────────┬────────┘
                               │
                    重复最多 K = 10 轮
                               │
                               ▼
                    ┌──────────────────────┐
                    │  最终答案            │
                    └──────────────────────┘
```

### 4.2 ★ 一个关键设计：准确率单调不减 ★

**原文的说法**：

> "since we iterate over the incorrect responses only, the accuracy sequence is **monotonically non-decreasing**."

**中文**：因为我们**只对错误的回答做迭代**，所以准确率序列**单调不减**。

**为什么这一点很重要**：

```
如果正确和错误都拿去重试 → 可能把对的改错（★ 这正是 R06 现象的来源 ★）
   ↓
只对错误的迭代 → 保证曲线只会往上或平 ── 永远不会往下
   ↓
★ 于是「曲线为什么平了」就只可能是「改不动」，而不是「改坏了」 ★
```

**这是一个很干净的控制设计。** 它把 R06 里"自校正会让性能**下降**"这个混杂因素甩掉了，
只留下"能不能**提升**"这一个问题。

**代价**：它需要一个**能判断对错的外部裁判**（因为有标准答案）。

**★ 这一点你必须在引用时说明 ★** —— 见本文 §10.2 的"最重要的一条限制"。

### 4.3 三种反馈机制（逐级增强，但都不给答案）

| 机制 | 名称 | 内容 | 由谁生成 | 是否泄露答案 |
|---|---|---|---|---|
| **F₁** | **Binary Correctness Feedback**（二元正确性反馈） | 只告诉"这个答案是错的" | —— | ❌ 不 |
| **F₂** | **Self-Generated Reactive Feedback**（自生成反应式反馈） | 求解模型**自己**分析自己的回答 | 求解模型 | ❌ 不 |
| **F₃** | **Strong-Model Reactive Feedback**（强模型反应式反馈） | ★ **最详细**：包含最终答案 + 完整解法（在可得时） | **更强的模型** | ⚠️ **不给答案本身，但给完整推理路径** |

**三级设计的目的**：

```
F₁ 只给「错」         → 信息量最低
F₂ 让模型自己找原因    → 信息量中等（但它自己找得到吗？）
F₃ 让强模型给完整解法  → 信息量最高
   ↓
★ 如果 F₃ 也救不回来，那"反馈质量不够"这个解释就破产了 ★
```

**⚠️ 注意 F₃ 的一个微妙之处**：它"包含完整解法" —— 这已经很接近给答案了。
**所以 F₃ 下的 plateau 是最有力的证据**：**连推理路径都给了，还是改不对。**

| 任务 | 与天花板的差距（10 轮后） |
|---|---|
| **AIME** | ★ **低 15–25%** ★ |

> **同一个模型、同一种算术、同样给了完整解法 —— 只是把数字换成十六进制，就没有一个模型能超过 20%。**

> 这排除了"数学能力不足"这个解释（十进制会做），

## 第 8 节 · 三种"为什么"以及排除了哪些

### 8.1 ✅ 保留的解释：置信度（semantic entropy）

**方法来源**：Farquhar et al., *Nature* 2024 —— *Detecting hallucinations in LLMs using semantic entropy*。

**做法**：对同一个问题采样多次，看答案的**语义聚类**有多分散。
- **语义一致** → 高置信
- **语义分散** → 低置信

**发现**（✅ 已核，Figure 6 / 17）：

```
改进率（improvement rate）
  │
0.8├───────────────────────────────╱────
  │                            ╱╱
0.6├───────────────────────╱╱╱╱
  │                   ╱╱╱╱
0.4├───────────────╱╱╱
  │          ╱╱
0.2├─────╱╱
  │  ╱╱
0.0├─╱───────────────────────────────────
  └────────────────────────────────────→ 语义熵（→ 置信度降低）
   低熵=高置信                    高熵=低置信
   ★ 接近 0 ★                     ★ 0.4–0.8 ★
```

**原文结论**：

> **模型对具体问题的置信度（用语义熵度量）可以预测反馈抵抗 —— 高置信度的预测对纠正保持抵抗。**

**另一个重要细节**：

> **初始置信度能很好地预测初始准确率，但很poorly地预测改进潜力。**

**这句话的含义很深**：

```
"我知道自己可能错了"  → 它会改
"我确信自己是对的"    → ★ 它不改 ★
   ↓
★ 而模型的"确信"和它的"正确"是两回事 ★
```

### 8.2 ❌ 排除的解释

| 被排除的解释 | 用什么排除的 |
|---|---|
| **模型过度自信（overconfidence）** | 用 semantic entropy 量化后，发现"高置信 → 低改进"这个关系**不是**简单的过度自信 —— ❓具体论证需查原文 |
| **数据熟悉度（data familiarity）** | 论文明确列为 ruled out |
| **反馈质量** | Table 1（FQ 只占 0–30.8%）+ Figure 4（F₃ 也够不到天花板） |
| **问题复杂度** | 合成任务（十六进制乘法是"简单任务"，仍然失败） |

### 8.3 ★ 一个特别值得记的发现：说与做的分离 ★

**✅ 已核**：

> 在所有模型和任务上，求解器都**声称**理解反馈（**> 95% 回答 "yes"**）
> 并且**声称**愿意更新（**> 96% 回答 "yes"**）
> **—— 但它们实际上没有做到。**

**中文**：

> **模型说自己懂了（>95%），说自己会改（>96%），但实际改不对。**

**这个发现的含义**：

```
模型的自述（"我明白了"）★ 不能作为它真的会改的证据 ★
   ↓
★ 任何依赖"让模型自我报告"的机制都是不可靠的 ★
```

**⚠️ 对你的研究直接相关**：

> **如果你的 harness 里有"让模型确认它理解了反馈"这一步 —— 这篇论文告诉你那一步是无效的。**
> **必须用行为（它真的改了吗）来判定，不能用自述。**

### 8.4 缓解策略（都没成功）

**✅ 已核，Figure 5**：

| 策略 | 效果 |
|---|---|
| **渐进升温**（progressive temperature increases） | 有改善 |
| **显式拒绝先前错误答案**（explicit rejection of prior incorrect answers） | 有改善 |
| **两者结合** | ★ **"仍然无法帮助模型达到目标性能"** ★ |

**注意"显式拒绝先前错误答案"这一条**：

```
把模型之前答错的答案从上下文里拿掉 → 它就"想不到"那个错误答案了
   ↓
这是 harness 层能做的事（★ 不是模型层 ★）
   ↓
有效，但不够
```

**这一条对你特别有参考价值** —— 它是**纯粹的 harness 干预**，而且论文给了它的效果上限。
